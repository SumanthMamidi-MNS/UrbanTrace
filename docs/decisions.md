# Decision log — UrbanTrace

One line per non-obvious technical choice: what, and why.

- **2026-09-15** — Perception emits **per-character probability distributions**, not argmax strings: the whole probabilistic model collapses to fuzzy matching without them.
- **2026-09-15** — Plate matching uses a **noisy-channel likelihood ratio marginalised over the unknown true plate**, not Levenshtein distance: edit distance has no calibrated probabilistic meaning and can't be fused with other evidence.
- **2026-09-15** — Association solved as **min-cost flow over a time-ordered DAG** (Zhang–Li–Nevatia), not greedy/Hungarian chaining: gives global optimality for the pairwise model and enforces "one event, one vehicle" for free.
- **2026-09-15** — **Hard contract between ingest (L1) and the linking engine (L3)**: lets the simulator (ground truth, metrics) and real video (realism) feed the same engine, and lets engine + UI work proceed in parallel.
- **2026-09-15** — **Simulator is the primary data source, real video is additive**: no public multi-camera city ANPR dataset with trajectory ground truth is obtainable in a week, and without ground truth there are no numbers to defend.
- **2026-09-15** — **SQLite via SQLAlchemy** for demo storage, Postgres as a drop-in: zero setup friction for an offline demo, same ORM if it ever scales.
- **2026-09-15** — **No Kafka/Spark/Timescale this week**; an in-process queue + WebSocket covers demo scale. Recorded as the documented production scale-out path rather than an omission.
- **2026-09-15** — **MapLibre + OSM** over Mapbox/Google: no API token, works offline at the demo table.
- **2026-09-15** — **rapidfuzz used only for candidate blocking, never for final scoring**: it exists to cut the O(N^2) pair space, not to make decisions.
- **2026-09-15** — **Clone detection reuses the kinematic hard gate** instead of a separate module: same-plate + impossible travel time + divergent appearance is already computed during scoring.

## Pre-build review pass (2026-09-15)

- **2026-09-15** — **Own successive-shortest-paths min-cost-flow solver instead of OR-Tools**: OR-Tools takes integer costs and ours are log-likelihood floats, and SSP yields the optimal vehicle count `k` in one pass (stop when the shortest augmenting path cost turns positive) rather than binary-searching `k`. `networkx` retained as a test oracle.
- **2026-09-15** — **Fixed 10-slot canonical plate representation with uniform posteriors for unread slots**, instead of a full edit-HMM: an unread character then contributes exactly zero to the LR (missing information, not evidence against), which is the correct handling of occlusion and far simpler to get right in a week.
- **2026-09-15** — **The spatio-temporal gate is the primary blocker; plate blocking only engages on candidate-budget overflow**: making a plate index the primary filter would silently reintroduce the exact brittleness the project exists to attack — a badly misread plate would never even become a candidate.
- **2026-09-15** — **Simulator corruption model pinned to published real-world figures** (per-read OCR 85–95%, appearance-only Re-ID rank-1 ~70%), enforced by a test in `eval/`: a self-written simulator can be tuned to flatter our method, so this is the guard that makes our results defensible.
- **2026-09-15** — **Python 3.12** (3.11 unavailable locally; no 3.12 incompatibilities in the stack).
- **2026-09-15** — Machine has an **RTX 3050 6GB**, so the Day-4 real-video path uses genuine YOLO + OCR + OSNet Re-ID rather than the CPU fallback.

## Day 1 build (2026-09-15)

- **Series slot left-aligned, number slots right-aligned** in the 10-slot canonical plate (`SS DD L_ _DDD`-style padding): mirrors how real Indian plates are written (no leading zeros; a 1-letter series sits immediately after the RTO code), and keeps blank-padding unambiguous for the OCR posterior model.
- **Clone injection is applied as a post-process over an already-generated vehicle population** in `sim/vehicles.py` (not inline in `sim/corruption.py`) even though the knob (`clone_fraction`) lives in `CorruptionConfig`: assigning a clone's plate requires picking another vehicle's *route*, which only exists once journeys are generated — corruption.py only ever sees one passage at a time. Clone sources are restricted to non-clone vehicles so a clone's copied plate can never be silently overwritten by a later clone assignment in the same pass.
- **Whole-plate per-read OCR accuracy (the 85-95% calibration band) is measured as exact 10-slot argmax match against the true plate**, over all non-missed events (occluded slots count as wrong unless they happen to argmax-match) — this is what "per-read accuracy" means in the published ANPR figures the PRD cites, not a per-character rate. Tuned defaults: `p_char_correct=0.99`, `p_occlude=0.03` in `CorruptionConfig`.
- **Appearance-only rank-1 retrieval (65-75% band) required two-level noise tuning**: a small per-vehicle identity offset around each (type, colour) class centroid (`EMBEDDING_CLASS_NOISE_SIGMA=0.05` in `sim/vehicles.py`) plus per-detection camera observation noise (`embedding_noise_sigma_min/max = 0.070/0.082` in `CorruptionConfig`). Naive noise sigmas (~0.5, chosen without accounting for 128-d unit-vector per-dimension scale ~0.09) collapsed rank-1 to ~0%; values were found by sweeping and verified stable (0.68-0.74) across 7 seeds.
- **City topology**: grid side length auto-scales to `ceil(sqrt(n_cameras * 1.5))` (min 4) so there's always headroom between camera count and node count; arterials are grid rows/cols 0 and mid-index upgraded to 80 km/h plus a few skip-chords (~3 cells) for long segments; the ring road is simply every edge between two boundary nodes upgraded to 80 km/h, rather than a separately-modelled loop.
- **`sim/generate.py` split into `generate_dataset()` (pure, in-memory) and `write_dataset()` (I/O)**: not in the architecture doc, but needed so tests (determinism, calibration, ground-truth integrity) can run the pipeline without touching disk.

**Open question for the lead** — appearance-only rank-1 is gallery-size-dependent, not a fixed simulator property: the calibration test (1500 vehicles, ~VeRi-776 scale) measures 68-74% rank-1 as required, but the full 50-camera/20k-vehicle run measures ~14.5% on an 8000-event sample. This isn't a bug — with only 40 (type, colour) classes and 20,000 vehicles, ~500 vehicles crowd each appearance cluster, so "nearest neighbour is a different same-looking vehicle" becomes common; real large city fleets have the same problem (many vehicles are genuinely visually identical), which is arguably a point *in favour* of the project's thesis that appearance alone doesn't scale and must be fused with plate + kinematics. Left as-is for Day 1; flagging in case the lead wants a different stance (e.g. more appearance classes, or explicitly caveating "70% rank-1" as a benchmark-scale number, not a city-scale one) before Day 2 fits the appearance LR density ratio on this data.

## Day 1b (2026-09-15)

Lead's verdict on the Day 1 open question above: the 15% city-scale rank-1 **was** a simulator bug (appearance space too coarse), not realism — real Re-ID embeddings carry fine-grained identity (make/model/damage/stickers), not just 40 type×colour buckets. Fixed. Also: the dense on-disk JSONL (7378 bytes/event, 755MB at 107k events) was flagged as a blocker for demo performance and repo size.

- **Appearance embedding made three-level hierarchical**: class (type, colour; ~40 buckets, unchanged) -> model archetype (a vocabulary of `N_ARCHETYPES=1200` unit vectors, `sim/vehicles.py`) -> per-instance quirk. All three components are mixed as **unit vectors** with weights `EMBEDDING_WEIGHT_CLASS=0.15`, `_ARCHETYPE=0.8`, `_INSTANCE=1.4`, then renormalised. The original (Day 1) bug: the per-instance term was raw, un-normalised 128-d gaussian noise, whose norm (~11.3) swamped the unit-norm class term regardless of its nominal weight — so the "class vs instance" mixing weights were silently meaningless from the start, and 20k vehicles really did collapse into ~40 indistinguishable buckets. Making every level unit-norm before mixing is what let the weights actually control anything.
- **Weight/archetype-count tuning had to be done against the real corruption pipeline, not a simplified proxy**: a fast numpy-only proxy (single fixed noise draw, exactly 2 observations/vehicle) was used for the initial broad search, but transferred poorly to the real simulator — the real pipeline gives each vehicle ~3.9 events on average (not 2), and extra same-vehicle repeats in the gallery mechanically inflate rank-1 for a given noise level. Final tuning (obs sigma, archetype count) was done by directly measuring `sim.vehicles`/`sim.corruption` output at both gallery sizes; the proxy was only useful for picking a good weight *ratio* cheaply, not the absolute noise level.
- **Camera observation noise retuned to `embedding_noise_sigma_min/max = 0.130/0.142`** (was 0.070/0.082) to compensate for the corrected (now-meaningful) mixing weights. Verified stable across 5 seeds: benchmark-scale (1500) rank-1 in 0.64-0.77, city-scale (20000) rank-1 in 0.43-0.44 (well clear of the 0.35 floor).
- **Rank-1 measurement methodology changed to "eligible queries (>=2 events) vs. full gallery"**, moved into `eval/metrics.py::appearance_rank1` and shared by the calibration test and the scaling report. The Day 1 version scored every event as a query against every other event, including vehicles with only one event ever (no possible correct match — always counted as wrong). That's a defensible stricter definition, but it collapses to noise at large gallery sizes if the query side is naively sub-sampled by event rather than by identity (a bug hit mid-fix: sub-sampling raw events out of a large multi-event-per-vehicle pool mostly produces queries with zero true match left in the sample, tanking measured rank-1 for reasons that have nothing to do with the embedding model). The fixed methodology sub-samples the query side by eligible identity, while always searching against the FULL gallery, so gallery-size crowding is measured honestly and stays comparable across gallery sizes.
- **Calibration test split into two** (`tests/test_calibration.py`): `test_benchmark_scale_calibration_matches_published_anpr_figures` (1500 vehicles, rank-1 in 65-75%) and `test_city_scale_rank1_does_not_collapse` (20000 vehicles, rank-1 >= 35% floor). Both run at `n_cameras=20` (not the production 50) purely for test speed — rank-1 at a given identity count depends on the embedding model and gallery size, not camera count, so this doesn't change what's being calibrated. Full suite: 32 tests in ~27s.
- **`eval/appearance_scaling_report.py`** generates `eval/reports/appearance_scaling.json`: rank-1 at gallery sizes 500/1500/5000/20000 (all seed 42, `n_cameras=20`). Measured curve: 500->0.82, 1500->0.72, 5000->0.60, 20000->0.44 — a clean monotonic decay, which is itself the evidence for fusing plate + appearance + kinematics rather than trusting appearance alone at city scale.
- **On-disk format made compact** (`engine/contracts/codec.py`, new `engine/contracts/store.py::EventStore`): a slot posterior's dense 26-or-10-symbol dict is replaced by only the entries above `SPARSE_THRESHOLD=1e-3` (rounded to 4dp), with a single sentinel int for the fully-uniform/occluded case; this needed `CorruptionConfig.posterior_group_leak` raised from 0.85 to 0.999 (and a small synthesised fallback leak-set added for characters with no defined confusable group, e.g. J/K/W/X/Y) so the true residual "rest of alphabet" mass is small enough in total that sparsifying + renormalising never perturbs a surviving entry by more than 1e-3 — this doesn't change `plate_argmax`/OCR accuracy at all, since argmax was already decided before the posterior is shaped. The 128-d embedding is written to a companion float16 `embeddings.npy`; `DetectionEvent` gained `embedding_ref: int | None` (row index) as storage bookkeeping only — the in-memory contract's `.embedding` is unchanged and always populated. `EventStore` is the only supported reader of the pair; on-disk JSON keys are short (`id`/`cam`/`t`/`pp`/`pa`/`pc`/`er`/`a`/`s`) as a wire-format-only optimisation, and `None` fields (`crop_uri`, `gt_vehicle_id`) are omitted rather than written as `null`.
- **Measured**: 107,476 events (50 cameras/20k vehicles/24h, seed 42) now serialise to 770.7 bytes/event (82.8MB total: 514.7 B/event JSONL + 256.0 B/event float16 embeddings), down from 7378 B/event (755MB) — a 13.9x reduction, under the 800 B/event target. `tests/test_storage.py` asserts the bytes/event target and round-trips (posteriors within 1e-3, embeddings within float16 precision after renormalisation) on every run.

## Day 1c — the zero-probability defect (2026-09-15)

**Principle** (this is what Day 2's plate LR rests on, and the answer when a judge asks what happens on an OCR error the confusion model didn't anticipate): **a slot posterior always retains background mass on every character in its alphabet — no character is ever assigned probability exactly zero.** `P(O|y) = PROD_k P(o_k|y_k)` is a product over slots, so a single zero sends the whole plate log-LR to `-inf` and hard-rejects a correct match, which is exact-string-matching's failure mode rebuilt inside the probabilistic model. An out-of-group OCR error must stay *unlikely*, never *impossible* — real OCR softmax never emits an exact zero either.

- **Root cause, found by measuring against ground truth on 20,000+ events**: Day 1b raised `posterior_group_leak` 0.85 -> 0.999 to shrink the on-disk sparse encoding (so the tiny "rest of alphabet" residual would round to nothing). That fixed a storage problem by corrupting the probability model: 0.44% of read slots gave the true character exactly 0.0 posterior probability, and 4.3% of events contained at least one such slot. Fixed by treating cause and symptom separately: `posterior_group_leak` reverted to 0.85 (sim/corruption.py) so the in-memory posterior is honest; storage compactness is now the codec's job.
- **Dropped the synthesised J/K/W/X/Y fallback leak-set** (`_FALLBACK_LEAK_SIZE`, sim/corruption.py): it existed only to manufacture a small leak target for characters with no real confusable group, purely to keep those slots' storage footprint tiny under the old (now-reverted) high-leak regime. It has no independent modelling justification — real OCR has no reason to specifically confuse "J" with two random synthesised look-alikes — and the codec's residual term (below) makes it unnecessary: a character with no real confusable group now correctly spreads its non-peak mass uniformly over the *whole* alphabet instead.
- **Codec (`engine/contracts/codec.py`) now carries an explicit residual key `"*"` per sparsified slot**, holding the true leftover probability mass after the kept entries. Decode spreads it back uniformly over every alphabet character not otherwise listed, so sparsification itself can never zero out a character (defence-in-depth alongside the `posterior_group_leak` revert — and alongside `plate_lr`'s own floor at the scoring layer, Day 2). A decode-time floor (`1e-9`) on every character is a third, purely defensive layer in case both upstream invariants are ever violated.
- **Cohort-structured encoding, not a magnitude threshold, decides what gets folded into the residual.** The corruption model always builds a posterior from up to three internally-*uniform* cohorts: the peak character, an optional confusable "leak" group (a handful of characters sharing one elevated value), and a "background" cohort (every other alphabet character sharing one small value). A single magnitude threshold can't safely separate "leak" from "background" — a common blank/no-group character's uniform background share (e.g. spread over 10-25 alphabet symbols) can exceed a tight 3-member leak group's per-character share. So the codec instead identifies the background cohort structurally: the lowest-valued group of >=2 identically-valued non-peak characters. That cohort folds into the residual (it reconstructs exactly, since it really is uniform); the peak and any real leak cohort stay explicit, preserving the noisy-channel signal `plate_lr` needs. This is also what keeps storage compact: without it, reverting the leak fraction made many individually-tiny "rest" characters cross the old flat 1e-3 threshold and get written out one by one, ballooning a synthetic measurement to ~2.3KB/event.
- **Byte budget raised 800 -> 1000 bytes/event** (`tests/test_storage.py`) to pay for the residual key (~10 bytes/slot in the worst case). Not spent, in the end: measured 786.2 bytes/event at full production scale (50 cameras/20k vehicles/24h, 107,254 events, seed 42) — under even the old 800 B target — because the cohort-structured encoding keeps the kept-entry count per slot to ~2-4 regardless of leak fraction.
- **New permanent regression guard**: `tests/test_zero_probability_guard.py` generates a >=20,000-event sample and asserts, for every non-uninformative (read) slot across every event, that the true character's on-disk-round-tripped probability is > 0. Re-verified at full production scale too (50 cams/20k vehicles/24h): 0 zero-probability slots out of 1,062,981 read slots.
- **Re-verified after the revert**: whole-plate OCR accuracy at full production scale measured 0.8808, inside the 85-95% published-figure band (`posterior_group_leak` only reshapes the posterior, not the sampled/argmax character, so this was expected to hold — confirmed, not assumed).

## Day 2 — scoring channels + fusion (2026-09-15)

- **`plate_lr`/`appearance_lr` factorise the noisy-channel LR as a marginalisation over the unknown true category** (plate group, colour, or type), not a hand-tuned distance/threshold: `num = SUM_true pi(true) P(a|true) P(b|true)`, `den` = product of the two marginals. Both channels share this exact shape (and the appearance channel's colour/type term literally reuses it via `_categorical_log_lr`), which is also why an unread/uninformative input to either channel provably contributes ~0 rather than needing a special case.
- **Plate/RTO groups use dense (26,26) / (10,10) numpy matrices** rather than dict-of-tuples, so a candidate pair's group contribution is one `np.outer` + two elementwise sums — cheap enough that the alignment search (5 candidate shifts) and per-group loop don't threaten throughput (measured ~500-1200 pairs/sec end-to-end through all three channels + fusion on a laptop CPU, no vectorisation across pairs).
- **Alignment search shifts one event's slots by ±1 at the series (index 4) and number (index 6) boundaries independently** (5 candidates including "none"), rather than the full 3x3=9 combined-shift grid: the architecture doc calls for "the small set of plausible shifts," and a boundary insertion/deletion is a single-character event, not two independent ones happening at once in the same pair.
- **Train/held-out split shares one city but uses different data seeds** (`engine/calibration/fit_priors.py::generate_train_holdout_datasets`), rather than two fully independent `generate_dataset(seed=...)` calls. Architecture.md §10 names seed-sharing as a risk to avoid, but a kinematic model's fitted (camera_i, camera_j, tod) lookup table is only meaningful evaluated against candidate pairs from *that same* camera network — two different seeds through `generate_dataset` would also regenerate two entirely different, incomparable cities. `generate_dataset` itself is unchanged (still one seed drives everything, for every existing caller); the split adds `generate_dataset_with_city` alongside it.
- **Kinematic model fits travel-time observations from ground-truth vehicle trajectories** (`collect_travel_time_observations`), not from a candidate-pair-scoring pass: this stands in for what a real deployment would learn from historical, confidently-linked trajectories, which the simulator's ground truth is the only available proxy for pre-Day-3 (gating/association don't exist yet to produce "confidently-linked" pairs some other way).
- **Sparse (camera-pair, time-of-day) buckets shrink toward a road-graph prior via a simple pseudo-count blend** (`SHRINKAGE_PSEUDOCOUNT = 5`), rather than a full hierarchical Bayesian model: cheap, and satisfies the explicit "never leave a pair unmodelled" requirement — zero observations means 100% weight on the road-graph estimate, which itself falls back to a wide/uninformative estimate if the pair is graph-unreachable.
- **`physically_impossible` is not a separate `LinkEvidence` field**: that contract was frozen Day 1 and Day 2 wasn't asked to change it. The information isn't lost — by construction `kinematic_lr == -inf` if and only if the kinematic hard gate fired, so Day 3's clone detector recovers the flag losslessly by checking that equality rather than a dedicated field.
- **Isotonic regression (scikit-learn) over Platt scaling** for score -> P(same) calibration: a summed log-odds from three independently-fit channels has no particular reason to be logistic-shaped, and isotonic makes no parametric assumption. `scikit-learn` added to `pyproject.toml` — it was already named in architecture.md §5's tech stack for exactly this, just not yet installed.
- **Calibration ECE is measured out-of-sample** (isotonic fit on TRAIN pairs, evaluated on HELD-OUT pairs), not fit-and-scored on the same pairs: isotonic regression is flexible enough (a free-form monotone step function) to fit its own training labels almost perfectly, so in-sample ECE reads as ~0 regardless of whether the calibration actually generalises. This isn't just a test nicety — `calibrate.py`'s public `fit_calibration`/`evaluate` split enforces the same discipline for real use.
- **Labelled evaluation pairs use "hard" negatives** (`eval.metrics.sample_labeled_pairs`): for each real same-vehicle consecutive pair, the negative is the closest-in-time *different*-vehicle event at the same destination camera, not an arbitrary random pair. Day 3's gating.py doesn't exist yet to supply real candidate pairs, and without hard negatives, a trivial time-gap heuristic would separate almost everything, making per-channel/fused AUC numbers meaningless.
- **Adversarial test (i)'s "badly misread plate" is 8-of-10 slots wrong at moderate (0.6) confidence, not all 10 slots peaked near-certain (0.97) on a different, otherwise-valid plate.** The near-certain version was tried first and correctly fails to rescue: it isn't a bad *read* of the true plate, it's a confident read of a *different* plate, indistinguishable by design from an actual different vehicle — rescuing that would be a calibration bug, not a feature. The moderate-confidence version is what "OCR had a terrible day but is still honestly uncertain" actually looks like, and appearance + kinematics do rescue it (see `tests/test_fusion.py`).

## Day 2b — stratified evaluation (2026-09-15)

**Principle**: evaluation negatives must be sampled per-stratum, not uniformly (or "hard" in only one dimension). A plate is a near-unique 10-character identifier, so a negative pair drawn from two unrelated vehicles is trivial on plate almost by construction — no amount of negative-sampling cleverness in time/space changes that. Reported as one scalar, this makes a plate-only system look sufficient, which is the exact opposite of this project's thesis, and it makes the one case the architecture exists for (a cloned plate) statistically invisible. This was caught by the lead measuring plate-only AUC directly on a clone-negative stratum (0.4945 — chance) against the first Day 2 pass's headline number (0.9999) on hard-in-time-space negatives, using `data/run1` (a pre-Day-1c dataset; unrelated to this fix, which is about negative-sampling methodology, not the corruption model).

- **Four named strata, each with its own positive/negative construction** (`eval/stratified.py`): **routine** (closest-in-time different vehicle, same destination camera — the prior Day 2 methodology, kept as the "everyday" baseline), **clone** (different vehicle, exact same true plate), **degraded** (positives with >=4 combined unread/misread slots across the pair), **plate-similar** (different vehicle, true plate within edit distance <=2). `routine`'s negative sampling now explicitly excludes any candidate sharing the anchor's true plate, so a same-plate hard negative can't quietly leak stratum-clone signal into the routine baseline.
- **Headline is a stratum x channel matrix** (`eval/reports/stratified_auc.json`, tracked via a `.gitignore` `!`-exception like `appearance_scaling.json`), not a scalar. `tests/test_stratified_auc.py::test_clone_stratum_plate_only_collapses_to_chance_but_fusion_holds` hard-asserts plate AUC < 0.60 and fused AUC > 0.90 on the clone stratum — this is the project's thesis encoded as a test, not a number to be re-tuned if it fails.
- **Measured** (held-out split: 6000 vehicles/20 cameras, clone_fraction=0.02, near_miss_fraction=0.02; degraded stratum measured on a separate higher-noise dataset sharing the same city): plate/appearance/kinematic/fused AUC = routine 1.000/0.998/0.860/1.000 (89.8% of holdout pairs), clone 0.565/0.997/1.000/1.000 (4.0%), plate-similar 0.923/0.998/1.000/1.000 (4.1%), degraded 0.996/0.998/0.924/0.999 (2.1% natural rate; n=4000 in the boosted stress sample). Frequency-weighted composite: plate-only 0.980, fused 0.99998. The clone stratum is the thesis case: plate-only (0.565, chance) versus fused (1.000) is the whole architecture's value proposition made visible, where the routine-only headline hid it completely.
- **`degraded`'s positive sample is drawn from a deliberately higher-noise dataset, not the calibrated default.** At the default `p_occlude=0.03`, "combined unread+misread slots across a pair >= 4" occurs on only ~2.1% of real pairs (n=323 out of ~14.5k in one holdout run) — enough to report as a natural frequency, but too few to trust an AUC computed from a small, noisy sample. A stress `CorruptionConfig` (`p_occlude=0.35`, wider occlusion runs, `p_char_correct=0.90`, lower peak-mass range — whole-plate accuracy ~24%) generates a large, clean S3 sample instead. This mirrors architecture.md §8's own stress-sweep methodology (OCR error 0→40%) rather than inventing a new one. The stratum's reported *frequency* still comes from the default-noise dataset, so the frequency-weighted composite isn't distorted by the artificially harsh sampling dataset.
- **Natural plate-similar (near-miss, non-identical) pairs are rare — measured 6 in an 8000-vehicle population** (edit distance <=2, excluding exact duplicates) — too few for a reliable AUC. Added `near_miss_fraction` to `sim.vehicles.generate_vehicles_and_journeys` (`_inject_near_miss_plates`): a fraction of non-clone vehicles get a plate that's another vehicle's state+RTO+series prefix with the number nudged by 1-2 (`_perturb_number_slots`, preserving digit width so a 3-digit number stays 3 digits). This is not a contrived adversarial construction: sequential registrations within one RTO genuinely produce plates like `MH12AB1234` and `MH12AB1235` — both real, both on the road, and a real ANPR system has to tell them apart just as much as it has to catch clones. `near_miss_fraction` defaults to 0.0 (opt-in), so no existing caller or test's behaviour changes.
- **`find_plate_similar_pairs` groups candidates by the 6-character state+RTO+series prefix before computing edit distance**, rather than an O(n^2) scan over the whole vehicle population: two plates differing by more than a couple of characters outside that prefix cannot be within edit distance 2, so this is exact for the injected near-miss construction and a reasonable, documented restriction for the "natural occurrence" measurement (a natural near-miss that instead differs *within* the prefix, e.g. one state letter off, is not counted — judged an acceptable gap given how these are actually generated: independently sampled true plates, not perturbations of each other).
- **Stratum frequencies use a disjoint precedence (clone > plate-similar > degraded > routine)** over every real same-vehicle pair in the holdout, so they sum to 1 and can weight a single composite AUC honestly — a pair is never double-counted across strata even though the underlying conditions (e.g. "is a clone" and "is degraded") aren't mutually exclusive in principle.

## Day 3 — lead decisions (2026-09-16)

- **Pairwise zip idiom**: `zip(path, path[1:], strict=True)` always raises (unequal lengths); use `zip(path[:-1], path[1:], strict=True)`. Fixed in `window.py` and a latent copy in `mincostflow.py` that no test covered.
- **Unlinked events become length-1 trajectories**: SSP correctly never spends flow on an event with no profitable link, but every detection must still be reported somewhere; dropping them would silently deflate ID-recall. Enforced by a full-day partition test (every event in exactly one trajectory).
- **Scoring vectorised with per-event precomputation**: scalar per-pair scoring ran ~1500 pairs/sec (~4h for the full 21.5M-pair run); the plate LR's denominators are per-event, so precomputing them leaves only a batched dot product per pair. A batched-vs-scalar agreement test (1e-6) guards correctness.
- **API contract frozen in `docs/api-contract.md` before either side was built**: lets the UI and engine proceed in parallel; the UI ships a contract-exact mock mode so switching to the live API is a single flag.
- **Non-finite log-likelihoods serialise as `null`**: JSON has no infinity, and the kinematic hard gate legitimately produces `-inf`.
- **Map renders the road graph as GeoJSON from `/api/city`, no tile server**: the city is synthetic and the demo must run offline, so external basemap tiles would add a network dependency and show a real map that doesn't match our roads.
- **Parallel work streams own disjoint directories; the lead owns `docs/`**: smaller parallel tasks with no shared files prevent both lost work and write collisions.

## Day 3 — UI (2026-09-16)

- **MapLibre pinned to v5, not v6**: v6's worker never initialised under Vite 8 in dev or production build; v5 renders offline with the worker in the main bundle.
- **Map labels as HTML markers, no text layers**: MapLibre text layers need a glyph/font server, which would break the offline demo.
- **UI mock mode is lazy-loaded behind `VITE_USE_MOCK` and implements the same typed client**: switching to the live API is one flag; the mock's eval reports are byte-identical copies of `eval/reports/*.json` (verified by the lead), so the Results page never shows invented numbers.
- **WHY panel is a waterfall from prior through each channel to `total_log_odds`**: the running sum visibly lands on the total, which makes "weak plate, strong appearance + travel time" legible at a glance; non-finite channels are shown and excluded from the sum.
- **Plate confidence bars on a "nines" log scale**: near-1 probabilities (0.99 vs 0.9999) are otherwise indistinguishable.
- **Clone stratum numbers moved after overlapping clones were added** (plate 0.565→0.477, kinematic 1.000→0.960, fused 1.000→0.998): expected and more honest — the earlier kinematic 1.000 was an artifact of disjoint clone routes.

## Day 3 — robustness and scale (2026-09-16)

- **Consensus decoding uses an ε-contamination likelihood, `(1-ε)·P_ocr + ε·U`, with ε=0.2**: a pure product let one outlier read veto a clear majority (a character in two confusion groups soaks up leaked mass from every read). ε was tuned on a separate-seed dataset, never on run1. The gain on run1 with ground-truth grouping is real but modest (3 reads 97.88%→98.30%, 4+ reads 99.88%→99.95%). ε=0.2 was the top of the sweep, so the optimum may be slightly higher; not pursued given the small effect.
- **Batched scoring accepted at ~40–65k pairs/sec against a 200k target**: float32 accumulation broke the 1e-6 batched-vs-scalar agreement test, so float64 was kept. Association is precomputed before the demo, so correctness wins over the remaining speed.
- **Exact dominance pruning of link arcs before min-cost flow**: an arc whose cost is ≥ exit(i)+entry(j) can always be replaced by ending the track at i and starting a new one at j (both arcs are free at capacity 1), so it is never needed for optimality. Removing such arcs is lossless and removes most of the ~207 gated candidates per event. The pure-Python SSP solver, not scoring, had become the bottleneck (projected hours on the full city).
- **Solve each connected component separately after pruning**: components share no event nodes, so the optimum decomposes exactly.
- **All `eval/reports/*.json` are tracked**: each is under 3KB and all are defence evidence, so per-file gitignore exceptions only invited reports being silently lost.
- **Measured effect of the exact solver fix** (full run1, morning build-up): dominance pruning keeps only ~2% of scored arcs (e.g. 511,280 → 9,014 in a 2,498-event window), and that is where nearly all the speedup comes from. Component decomposition helps far less than expected: at rush hour the largest component spans ~88% of a window's events, because dense traffic links almost everything to something. Kept because it is exact and cheap, but the credit belongs to pruning.
- **Full-coverage trajectories make ID-precision = ID-recall = IDF1**: every event is assigned to exactly one trajectory and ground truth also covers every event, so IDFP = IDFN. This is expected, not a metric bug; worth saying before a judge asks.

## Live-data verification (2026-09-18)

- **Root cause of over-merging: a constant, far-too-weak prior.** `prior_log_odds` used `DEFAULT_EXPECTED_CANDIDATES = 5` (prior −1.39) for every link, and nothing overrode it; the gate actually produces ~218 candidates/event (prior ≈ −5.4). Every link got ~4 nats of unearned odds, so the solver merged vehicles through links it itself scored as more-likely-different (e.g. `traj_018419`: two unrelated plates joined through total log-odds −0.32). **Fix: a per-successor prior, −log(n_candidates − 1)**, which also adapts to rush-hour density where over-merging is worst. All full-city numbers before this fix are labelled pre-fix.
- **SQLite database lives outside OneDrive** (`%LOCALAPPDATA%\sutra\sutra.db`, via `SUTRA_DB_PATH`): the same ingest took 335s locally versus >3h (209 CPU-s) stalled inside the OneDrive-synced project folder, because every SQLite write triggers a sync of a 600MB file.
- **Screenshots are not evidence of a blank map**: the browser tool can't capture the WebGL canvas when the window is unfocused. Map health was verified with `queryRenderedFeatures` (174 road features, 50 cameras rendered) and a centre-pixel read.
- **Real-data demo story differs from the mock**: a single-character misread lowers the plate LR (≈13.7 vs ≈18.7) but rarely flips it negative; the headline demo is consensus repair (e.g. `UP60VU`/`UP60QU` → `UP60YU` at 99.8%), not the mock's "plate argued against the link" case.

## Kinematic channel fix (2026-09-22)

- **Kinematic null hypothesis fitted empirically from negative gated pairs, not assumed uniform**: an unrelated vehicle in the same gate travels the same road, so it arrives at a similar time; a uniform p0 made any plausible Δt look strongly like a match (+6.4 nats on a wrong link seen earlier). Fitted like the appearance channel, per camera pair and time-of-day with shrinkage to a pooled null; the v_max hard gate and `physically_impossible` signal are unchanged.
- **Effect on the ablation** (20 cams / 2,500 vehicles / 4h): plate+kinematic 0.901 → **0.977** (now above plate-only 0.968); all three 0.981 → **0.992**, the best row — the success criterion that every added channel helps. 119 targeted tests pass, including the clone-stratum assertions.
- **Two claims corrected by the honest ablation, not hidden**: (1) with calibrated channels, greedy chaining nearly matches min-cost flow (0.991 vs 0.992) — the solver's large earlier lead (0.981 vs 0.899) was an artefact of a miscalibrated channel feeding greedy bad links; the solver's remaining value is structural (guaranteed one-read-one-vehicle, global consistency), not a big accuracy margin. (2) Without the plate, appearance + travel time reach only 0.388: they cannot overcome a ~1-in-218 prior alone. The channels are complementary support for the plate, not substitutes for it.

## Synthetic OCR data realism (2026-09-22)

- **Lead reviewed rendered samples before training and sent back four defects**: series letters must exclude I and O (Indian RTO convention, and in the plate font O is indistinguishable from 0 — a label-noise source); add the HSRP blue "IND" strip and chakra hologram; composite onto background with perspective warp, small rotation and random crop margins, since real detector crops are never tight and frontal; add character size/spacing/stroke jitter. A model trained on clean frontal crops would score well on synthetic tests and poorly on real plates.
- **Synthetic occlusion is partial (a band ≤ ~half the text height inside the text region), never full-height**: a full-height band erased characters the label still named, which trains the recogniser to confidently hallucinate unseen characters — directly contrary to the engine's need for unread characters to stay uncertain. Genuinely unreadable plates are left to low model confidence at inference.
- **The kinematic fix did not transfer to full-city density, and is kept anyway**: small ablation city 0.981 → 0.992, but full city IDF1 0.9899 → 0.9891 with ID switches 754 → 1,893 and more over-splitting (20,988 vs 19,995 true). At rush hour a *correct* travel-time model is barely discriminative, so weak-plate true links no longer clear s > 0; the old mis-specified null's +6 bonus had been carrying them — right for the wrong reasons. Reverting to a known-wrong model because it scores better on the evaluation day would be tuning on the test set. **Instead the link decision threshold is calibrated (a bias β, link iff s > −β) on a separate training day at full-city density**, then applied once to run1. Pre-fix full-city numbers kept in `eval/reports/trajectory_metrics_pre_kinfix.json`.
- **Lesson recorded: the small ablation city is not representative of full-city density.** Channel-level conclusions from it must be re-checked at full scale before they are claimed.
- **First synthetic OCR run (20 epochs, 60k plates): whole-plate 88.0%, character 98.2%, clean plates only 92.8%**, validation plateaued at ~90% from epoch 12 — a systematic error, not undertraining. Diagnosed from raw CTC decodes: 73% of clean failures were two-line plates losing the LAST character of the top row (e.g. `GJ49TV` → `GJ49T`), because the HSRP strip pushed text toward the right edge and rotation/tight crops clipped it while the label still named it. **Fix: the renderer tracks every character's bounding box through all transforms and re-samples until every labelled character is fully visible**, enforced by a test — the same principle as the occlusion fix: a label must never name a character the image does not show.
- **Whole-plate confidence is the product of per-character probabilities, not their mean**: ten characters at 0.98 average to 0.98 but are all right only ~82% of the time; the mean inflated the calibration error (ECE 0.112).
- **OCR probabilities are temperature-calibrated on the validation set** before being mapped to plate slots, because the linking engine treats them as evidence — an over-confident OCR would make every plate comparison over-confident too.

## Link threshold and OCR v2 (2026-09-22)

- **Link bias β = 2.0 nats, chosen on a full-scale training day (seed 20260922, 50 cameras, 19,990 vehicles, 24h), never on run1.** Across β ∈ {−0.5, 0, 0.5, 1, 2, 3}, IDF1 (0.9900 → 0.9919), ID switches (1,553 → 1,052, −32%), fragmentation (833 → 578) and the trajectory count (20,808 → 20,527 vs 19,990 true) all improve monotonically up to β=2. The calibration script's automatic 0.003-IDF1 margin rule would have kept β=0; overridden because every metric moves together, so this is signal, not noise. Earlier sweeps at 4 and 15 cameras were flat because a small network has no candidate-pool difficulty; they are kept as `link_bias_calibration_scale002.json` and superseded.
- **OCR v2 after the clipping fix: synthetic whole-plate 88.0% → 95.1%, clean 92.8% → 99.6%, character 99.1%.** Hardest conditions remain occlusion (76.2%) and dirt/damage (83.8%). Still synthetic — the PRD claim waits for the real test split.
- **Temperature T = 1.18 fitted on per-character CTC NLL is kept even though whole-plate ECE moved 0.015 → 0.021**: the engine consumes per-character posteriors, which is exactly what T was fitted for; the product-based confidence metric alone had already brought whole-plate ECE from 0.112 to 0.015.
- **Real two-line Indian plates wrap inconsistently, and aspect ratio is unreliable on loosely-boxed crops, so inference does not depend on a layout label**: every crop is read both as one line and as two rows; the two-row reading is concatenated before grammar alignment (wrap position becomes irrelevant) and the higher-probability reading wins. For fine-tuning, each real two-row crop's row split is found by forced alignment — the split of the known label that the synthetic-pretrained model scores highest — stored in the CSV for audit.
- **β = 2 transferred from the training day to the unseen test day**: full-city run1 IDF1 0.9891 (β=0) → **0.9914** (β=2), ID switches 1,893 → 1,299, trajectories 20,988 → 20,670 vs 19,995 true, solve 655s → 220s. Reported with the honest caveat that ID switches remain above the (mis-specified) pre-fix model's 754, although IDF1 — the headline metric — is higher. Pre-fix and β=0 reports kept (`trajectory_metrics_pre_kinfix.json`, `trajectory_metrics_beta0.json`).

- **The synthetic-only model is also scored on the real test set**, so the report shows the domain gap and what real fine-tuning buys, not just the final number.
- **Detector evaluation on `plate_boxes_2k` was mostly invalid**: 1,902 of 2,083 images are already-cropped plates whose box is the whole image; a plate detector finds nothing in a picture that *is* the plate. Diagnosed from raw decodes — the evaluation matches the raw decoding exactly, so this is genuine misreading (1–2 character substitutions, doubled/dropped characters around real plates' dot separators and varied fonts), not a pipeline bug. A single synthetic font plus 546 unique real training plates is too little to learn real Indian plate typography.
- **Response: a pretrained plate-specific OCR (fast-plate-ocr, MIT, ~220k global plates; approved by the user) is evaluated zero-shot and fine-tuned on the same real split**, alongside a longer (60-epoch) fine-tune of our CRNN; and the team is sourcing the ~16k-image "Indian Licence Plate Dataset in the wild". fast-plate-ocr predicts a per-position distribution, which maps onto the 10-slot posterior with the same grammar alignment and background-mass invariant.

The PRD's OCR requirement is separate and is reported honestly on its own terms.

More epochs will not help; more real data (the "in the wild" set) or a pretrained plate model (fast-plate-ocr, being evaluated) will.
- **Detector RGB bug confirmed and fixed**: Ultralytics assumes numpy inputs are BGR and flips them; `PlateDetector.detect()` passed RGB, so every image reached the detector channel-swapped (yellow/white plates look bluish). Fixed inside `detect.py`. All earlier detector numbers were measured with this bug and are superseded.
- **"Series absent" is a peaked blank, not uniform** (fixed in both `fpo_adapter.py` and `ctc_to_slots.py`): when digits follow the RTO code directly, the plate grammar is positive evidence there is no series (older plates like `AR15 2019`); treating it as "unread" made the slots uniform and argmax picked 'A', inventing `AA`. Uniform is reserved for genuinely unreadable slots. fast-plate-ocr zero-shot 49.4% → 51.4%.
- **fast-plate-ocr publishes trainable Keras weights** (`cct_s_v2_global.keras`, same release as the approved ONNX), so fine-tuning starts from a model pretrained on ~220k global plates rather than from scratch. - **Its Keras/TensorFlow training runs on CPU on native Windows** (TensorFlow ≥ 2.11 has no native-Windows GPU support): ~30 s/epoch on 929 crops is acceptable; WSL2 would be the route if data grows (e.g. the 16k-image in-the-wild set).
- **`fast-plate-ocr export --format onnx` fails on Windows** (reopens a still-open `NamedTemporaryFile`, which Windows forbids); `train_fpo.py` performs the same export → simplify → validate steps with ordinary file handles instead of patching the library.

## Contract v2 and congestion realism (2026-09-25)

- **Watchlist matching is probabilistic and runs on both the single read and the trajectory consensus** (threshold P ≥ 0.5): verified on the real database — `traj_020667` (`UP60YU___3`, two of seven reads misread as `UP60VU`/`UP60QU`) raised a watchlist alert via the trajectory consensus at P = 0.998. Each (entry, trajectory) alerts once; later matches are hits. Watchlist alerts are severity "high".
- **Single-read watchlist matching uses the read's own posterior, not `decode_trajectory`**: the consensus decoder's ε-contamination (built for multi-read fusion) caps any single read's match probability near 0.19, which would make single-read matching impossible.
- **Stored event posteriors keep top-5 characters per slot; the rest of each slot's mass is spread uniformly** when reconstructing a full posterior for matching — preserves the background-mass invariant.
- **Corridor speeds use road-graph shortest-path distance (length-weighted) over observed travel time; links implying > v_max are excluded** as clone evidence, not speed.
- **The simulator gets density-dependent travel times (BPR: t = t_free·(1 + 0.15·(v/c)⁴))**: the real-database check showed corridor speeds ≈ free flow at every hour (congestion index ≈ 1.0), because vehicles drove at the limit regardless of traffic — so the PRD's congestion-bottleneck analytics had nothing to detect. BPR is the standard traffic-engineering link function; capacities are tuned on a non-evaluation seed so peaks reach v/c ≈ 0.9–1.3. A `congestion` knob keeps the old behaviour reproducible. The headline evaluation will move to a new congestion-on day (run2); run1 results are retained as the earlier record.
- **Congestion setting is read from the evaluation dataset's `config.json` and applied to every training/priors dataset** (`run_pipeline`, `calibrate_link_bias`, `ingest --build-demo`): the simulator library defaults `congestion=False` for byte-identical reproduction while the CLI defaults it to True, so without this the travel-time model would silently be trained on free-flow traffic and evaluated on congested traffic. A guard test enforces it.
- **Congestion calibrated against what ANPR can observe (camera-to-camera speed), not edge-level v/c**: the first capacity (320 veh/h, tuned for edge v/c ≈ 0.9–1.3) produced only a 1–3% corridor slowdown at peak (worst corridor 0.97 of free flow), because camera-pair routes cross bottleneck edges for only part of their length. Swept at full scale on tuning seed 777 and pinned to typical Indian-metro peak behaviour: **arterial capacity 140 veh/h → peak median 0.84, bottlenecks (p5) 0.42, night 0.99** of free-flow speed. Verified the model is wired correctly first (capacity 40 → peak median 0.62).
- **Known simulator limitation, recorded not fixed**: every trip enters and leaves at the city boundary (no intra-city home–work trips), so the grid interior carries almost no traffic and congestion concentrates on the ring road; OD analytics therefore reflect through-traffic only.
- **The headline evaluation moves to run2** (seed 43, congestion on, `C:/sutra-data/runs/run2`); the link threshold is re-calibrated on a congested training day (seed 20260926). run1 results remain as the earlier record (`*_run1.json`, `trajectory_metrics_pre_kinfix.json`, `_beta0.json`).
- **Congestion exposed a real recall hole in the candidate gate.** On the congested training day the link-threshold sweep plateaued at IDF1 ≈ 0.88 (β barely mattered), with ~30k trajectories for ~20k vehicles. Measured on congested run2: gate true-predecessor recall 0.997 at night but **0.68 at 08h and 0.70 at 17h**, while every true link that reached scoring had total log-odds ≈ +23 (none ≤ 0). The whole loss was the gate: its window is the fitted log-normal ±3σ, only ~1.4–1.6× typical time under free-flow noise, while jammed bottleneck trips take ≥ 2.4× free flow.
- **Fix principle: the gate may exclude only the physically impossible, never the merely slow.** The lower bound (v_max) is unchanged — clone detection depends on it; the upper bound gets a floor of free-flow time × a congestion tail factor justified from the BPR model (v/c = 2 → 3.4×) and the calibrated bottleneck speeds (down to ~0.23× free flow). The kinematic LR already weighs slowness downstream. The factor is justified from the model, not tuned on run2, which is only measured.
- **This vindicates the Day-0 architectural warning** that the gate decides the recall ceiling of the whole system; the uncongested simulator had hidden it, which is why realistic congestion was worth adding.
- **Gate congestion floor verified on congested run2**: true-predecessor recall now ≥ 0.993 at every hour (08h 0.688 → 0.993, 17h 0.695 → 0.994, 18h 0.768 → 0.997; nights unchanged at ~0.998). Cost: mean gated candidates per read 4.5× higher (1,026; 1,696 at 08h) — the floor applies at every hour, not only when congestion occurs. Accepted for correctness; a learned per-time-of-day tail factor would cut the night-time overhead and is noted as a later optimisation (`eval/reports/gate_recall_by_hour*.json`).
- **Calibration sweep narrowed to β ∈ {0, 1, 2, 3}** (new `--betas` option): with 4.5× more candidates each full-day solve is slower, and both earlier sweeps peaked inside that range; the full default grid remains available.
- **β = 5 for the congested regime, chosen on the congested training day (seed 20260926)**: IDF1 0.9463 (β=0) → 0.9632 (3) → 0.9665 (4) → **0.9693 (5)** → 0.9691 (6). IDF1 was the pre-declared selection metric and flattens at 5; ID switches keep falling beyond it (2,754 → 2,381) but are not the selection criterion. The first sweep ended at the grid edge (β=3) and was extended rather than accepting a boundary optimum. The higher β than the uncongested regime (2) is expected: with travel time less informative at rush hour, genuine links carry smaller positive log-odds and need a lower acceptance threshold.
